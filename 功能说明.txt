============================================
    微信群聊 AI 总结 - 功能说明
============================================

启动后菜单栏会出现 💬 图标（在屏幕上方），点击即可操作。
以下介绍所有功能和使用技巧。
完整安装、隐私边界、公开 fork 说明和命令行维护入口，请看 README.zh-CN.md。



============================================
    一、群聊总结（核心功能）
============================================

每个群聊点开后有两个选项：

  📝 总结新消息
  ─────────────
  自动读取「上次总结之后」的所有新消息，
  发送给 AI 生成总结，然后自动弹出总结文件。

  • 首次使用会读最近的消息（最多 500 条）
  • 之后每次只读「上次到现在」的新消息
  • 总结完成后自动标记已读位置（书签）

  🔧 自定义总结
  ─────────────
  不按书签，手动指定总结范围。两种方式二选一：

  • 输入条数：如 100 → 总结最近 100 条消息
  • 输入分钟数：如 30m → 总结最近 30 分钟内的消息

  适合回顾特定时间段、或跳过部分消息重新总结。

  📅 按天总结
  ─────────────
  通过下拉菜单选择年、月、日，总结指定某一天的群聊消息。

  • 默认选中今天，选完日期点开始即可
  • 适合回顾某天群里都聊了什么



============================================
    二、分组管理
============================================

把常看的群聊归到一起，方便批量操作。

  新建分组
  ─────────────
  菜单底部有「📂 ✨ 新建分组…」，输入名称即可。
  比如：工作群、购物群、学习群。

  添加群聊到分组
  ─────────────
  点开某个分组 → 「➕ 添加群聊…」
  会列出所有可添加的群聊，输入序号即可，
  多个用逗号分隔（如 1,3,5）。

  从分组移除
  ─────────────
  在分组内某个群聊的子菜单点「❌ 从分组移除」。

  删除分组
  ─────────────
  在分组子菜单底部点「🗑️ 删除分组」。
  仅移除分组，不影响群聊本身和历史总结。

  🚀 一键总结（分组批量总结）
  ─────────────
  在分组子菜单中点「🚀 一键总结」，
  会把该分组内所有群聊的新消息汇总到一份报告中。
  适合每天快速过一遍多个群的动态。



============================================
    三、关键词搜索
============================================

点击菜单中的「🔍 关键词搜索」进入搜索。

  搜索条件
  ─────────────
  • 关键词：多个用空格分隔，必须全部同时出现才命中
  • 开始日期：必填，格式 YYYY-MM-DD（如 2026-03-01）
  • 结束日期：选填，留空则为今天
  • 群聊范围：默认「全部」，也可输入序号指定
  • AI 总结：勾选后用 AI 整理搜索结果；不勾选则显示原文

  ⚠ 注意
  ─────────────
  • 开始日期是必填的，格式必须是 YYYY-MM-DD
  • 留意对话框底部的「用 AI 总结搜索结果」复选框，
    勾上会调用 AI 对搜到的消息做归纳；不勾则直接列出原文
  • 搜索是只读的，不会影响任何书签或已读状态



============================================
    四、总结记录
============================================

  菜单中的显示
  ─────────────
  • 📝 最新的一条总结会直接显示在菜单中，
    展开可以预览前几行、复制到剪贴板、或打开完整文件
  • 📋 最近总结：列出最近 15 条历史总结，点击即可查看

  文件存储
  ─────────────
  所有总结都保存在 ~/.we-groupchat-obsidian/ 目录下的 .txt 文件中，
  文件名包含群名和时间戳，可以随时翻阅。
  也可以在菜单中点「📁 打开总结目录」直接打开。



============================================
    五、AI 服务
============================================

支持以下 AI 服务，在设置中切换：

  • 通义千问（默认） — 阿里云，国内访问相对方便
  • DeepSeek         — 性价比高
  • Ollama 本地      — 完全离线，无需 Key
  • Claude           — Anthropic
  • OpenAI           — GPT 系列

切换 AI 服务后，需要设置对应的 API Key。
Key 安全存储在 macOS 钥匙串中，不会明文保存到文件。



============================================
    六、使用技巧
============================================

  群聊列表刷新
  ─────────────
  • 推荐手动刷新：点击菜单顶部的「刷新群聊列表」
  • 也可以在设置中开启「自动刷新」，打开菜单时自动更新，
    但会有一点延迟（需要等几秒列表才出来）
  • 默认显示最近的 50 个群聊

  什么时候要「🔄 刷新数据源」
  ─────────────
  • 微信更新后，先运行「健康检查.command」
  • 如果看到通知「发现 X 个新数据库」，
    说明微信新增了数据库文件，点菜单中的「🔄 刷新数据源」即可
  • 重新登录微信账号后，也需要刷新
  • 刷新数据源可能需要输入电脑密码（管理员权限），请按终端提示操作

  书签机制（有时会有几条的误差，手动刷新群聊列表）
  ─────────────
  • 每次总结后，程序会自动记录「读到哪里了」（书签）
  • 下次点「📝 总结新消息」时只读新增部分，不会重复
  • 菜单中每个群聊会显示上次总结时间和新消息数量
  • 如果想重新来过，去设置中点「重置所有书签」

  自定义总结的使用场景
  ─────────────
  • 想回顾更早的消息：用条数，如输入 200
  • 想看某个时间段：用分钟数，如 60m = 最近一小时
  • 自定义总结不受书签限制，可以随时回看

  显示群昵称（备注名）
  ─────────────
  • 在设置中可以开关「总结中显示群昵称」（默认开启）
  • 开启后，总结中的群成员名字会优先使用你设置的备注名
  • 优先级：你的备注名 > 群名片 > 微信昵称
  • 适合群成员多、昵称难辨认的群聊



============================================
    七、关注推送、Obsidian 和 Daily Digest
============================================

关注推送适合盯“不是每条都重要，但错过会可惜”的群聊信息。

  配置方法
  ─────────────
  • 双击「配置关注推送.command」
  • 选择一个或多个群聊
  • 写下关注描述
  • 选择 AI provider，配置 API Key
  • 配置 Obsidian vault 或使用默认 Markdown 输出目录

  输出位置
  ─────────────
  默认知识库数据库：
    ~/.we-groupchat-obsidian/monitor_knowledge.db

  默认 Markdown 输出：
    ~/.we-groupchat-obsidian/obsidian_knowledge/

  如果配置了 Obsidian vault，默认写入：
    微信群聊/关注推送/

  笔记会按「群聊 / 分类 / 笔记」组织，并生成 link-only 日期索引：
    00-按日期.md

  单篇知识笔记按资源形态区分：
  • 普通主题：不加标题前缀
  • 链接主题：[链接]
  • 文件主题：[文件]
  • 同时含链接和文件：[链接+文件]
  正文保留摘要、关键事实、资源、相关主题和来源窗口。文件条目会记录文件名、
  消息时间和发送者；本机对应月份目录存在时会提供目录 shortcut，但不会复制
  微信附件，也不保证直接定位到唯一文件。

  Daily Digest 归档：
  • 当前月份：Daily Digest/YYYY-MM-DD Daily Digest.md
  • 更早月份：Daily Digest/YYYY-MM/YYYY-MM-DD Daily Digest.md
  Digest 中的主题标题是 wiki links，可以跳回对应的单篇知识笔记。

  旧版曾经生成过「按日期/YYYY-MM.md」月度 archive。当前版本不再创建月度
  archive 文件夹；完整历史保留在 root-level 的 00-按日期.md link map 中。

  通知分层
  ─────────────
  • P1/P2：系统通知、Review Queue、知识库 note、Daily Digest
  • P3：知识库 note、Daily Digest，不弹单条通知
  • 菜单栏「关注推送 → 后台通知：开/关」控制所有自动 banner；关闭后
    监控、知识库写入和 Daily Digest 仍继续，手动操作反馈与通知测试仍可用
  • Resource Lead：有人表示可以私发、晚点发、repo 还没公开，或群友开始索要资源，
    但当前窗口还没有文件/链接时，会作为 follow_up_resource 进入 Review Queue
  • 远程链接预览默认关闭；只有显式设置 monitor_fetch_links: true 后，才会请求消息里的公开 URL

  常用维护命令
  ─────────────
  .venv/bin/python scripts/daily_digest.py
  .venv/bin/python scripts/review_queue.py list
  .venv/bin/python scripts/review_queue.py show <item-id>
  .venv/bin/python scripts/review_queue.py mark <item-id> reviewed
  .venv/bin/python scripts/organize_obsidian.py --date-indexes-only



============================================
    八、MCP Server（高级功能）
============================================

支持通过 Claude Desktop 或 Claude Code 直接查询和总结微信消息。

  配置方法
  ─────────────
  在 Claude Desktop 配置文件中添加：
  ~/Library/Application Support/Claude/claude_desktop_config.json

  {
    "mcpServers": {
      "we-groupchat-obsidian": {
        "command": "/项目路径/.venv/bin/python3",
        "args": ["/项目路径/mcp_server.py"]
      }
    }
  }

  配置完成后，可以在 Claude 对话中直接：
  • 查询群聊列表
  • 读取聊天记录
  • 让 AI 总结指定群聊的消息
  • 搜索关键词
  • 查看聊天图片和表情包
  • 发送微信消息（默认关闭，需 mcp_send_mode 和辅助功能权限）

  消息发送（默认关闭）
  ─────────────
  MCP Server 默认偏只读。如果确实需要发送消息，必须先在本地配置中显式选择发送模式：

  {
    "mcp_send_mode": "dry_run"
  }

  可选模式：
  • disabled：永不发送
  • dry_run：只回显目标和内容，不触碰微信
  • allowlist：只允许发送到 mcp_send_allowlist 里的稳定 username
  • enabled：允许发送到非空目标

  所有非 disabled 模式都拒绝空目标；allowlist 请用 example@chatroom 这类稳定 username，
  不要用群显示名。

  enabled / allowlist 通过后，AI Agent 可以通过微信界面自动发送消息：
  • 指定群聊或联系人名称发送；空目标会被拒绝
  • 发送使用 macOS 原生 UI 自动化（CGEvent），全过程在微信界面操作
  • 发送后自动验证：去数据库查最近的消息确认是否成功
  • 窗口大小变化不影响发送，每次自动计算输入框位置

  ⚠ 发送消息需要额外权限：
  系统设置 → 隐私与安全性 → 辅助功能，
  授权运行 MCP Server 的应用（如终端、Claude.app）。



============================================
    九、数据安全
============================================

  关于数据安全
  ─────────────
  • 程序只读取微信数据库的副本，不会修改微信的任何文件
  • 消息内容只发送给你选择的 AI 服务，不经过其他服务器
  • 如果使用 Ollama 本地模型，消息完全不会离开你的电脑
  • API Key 存储在 macOS 钥匙串中，受系统级加密保护
